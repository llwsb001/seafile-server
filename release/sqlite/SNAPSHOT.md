# Linux SQLite 停服快照与恢复

快照记录同一个实例根目录下的 `conf/`、`ccnet/`、`seafile-data/`、`seahub-data/`、`seahub.db` 及已有的 SQLite 日志。对象目录随 `seafile-data/` 一起保存。归档清单记录目录和文件权限、文件大小及 SHA-256。准备恢复时另行取得原 C 与候选 Go 发行包，记录版本与摘要。 [发行目录布局](README.md#验证与安装布局)

脚本面向 Linux 上使用本地对象存储及标准布局的 SQLite 实例。用原服务账号运行，恢复出的文件归运行账号所有。归档保留普通权限位，含配置和用户数据，输出模式为 `0600`。在恢复演练凭部署记录重新提供外部密钥，例如 `JWT_PRIVATE_KEY`，并核对遗留配置引用的绝对路径指向恢复实例。

## 保存快照

关闭客户端同步、Web、WebDAV 和管理 RPC 的写入口，等已确认的写入发布。在 Go 实例等待写入队列排空并核对统计与 head，然后停止通知、Seahub 和核心相关进程。检查外部定时任务也已退出。工具在整个快照期间持有与发行启动脚本共用的实例操作锁，并检查实例 PID 文件以及各版本的 `runtime/seafile.sock`。通过其他途径启动的写入方也须停服。

```sh
"$VERSION_DIR/seafile/bin/seafile-sqlite-snapshot" backup "$INSTANCE" "$ARCHIVE"
```

`ARCHIVE` 是实例目录外的新文件路径，所在目录需预先创建。脚本复制已停止写入时的文件，按归档内容重验全部文件的摘要，并在独立副本校验六个 SQLite 数据库，包括复制的 WAL 或回滚日志。归档通过后，命令发布文件并输出其 SHA-256。备份或校验失败时，新输出路径保持空缺。临时校验目录最多需要接近实例数据大小的额外空间。

## 在新目录恢复

在可写的恢复根目录父目录下选好空缺的路径。将快照页输出的 SHA-256 保存在部署记录，在恢复时提供给命令。省略 `--sha256` 时，工具依然用归档内清单核对每个文件。

```sh
"$VERSION_DIR/seafile/bin/seafile-sqlite-snapshot" restore "$ARCHIVE" "$RESTORED_INSTANCE" \
  --sha256 "$ARCHIVE_SHA256"
```

恢复工具先验证全量文件，检查路径、权限和 SQLite 完整性，再发布新目录。完整性检查在额外数据库副本执行，恢复目录保留快照中的 SQLite 文件及其原始日志。符号链接和特殊文件使快照校验失败。旧实例中的外部挂载、密钥服务和自定义数据路径按部署记录单独恢复。

归档版脚本使用 Linux 系统的 Python 3.10 或更新版。从源码检出运行时可使用 `uv run --script release/sqlite/snapshot.py`，参数相同。

## 恢复验收

1. 在 C 持久化库引用和两个可辨识的文件，冻结当前和历史 SHA-256。用带已提交事务的 SQLite WAL 样本独立验收日志回放。停止写入并创建归档。
2. 把归档恢复到两个互相独立的新目录。分别解包锁定 C 和候选 Go 发行物，确认其各自 PID、RPC 路径、配置和对象目录指向当前的恢复目录。
3. 在停服恢复副本执行 `seaf-fsck` 检查。分别启动 C 和 Go，读取原来的资料库、文件与历史。通过 Web 或 RPC 继续写入，重启后验证新内容及原有权限。
4. 依次模拟活动 PID、RPC socket、同名归档或实例路径、摘要损坏和意外中断。核对原目录及归档未受影响，已发布的恢复目录仍能启动。
5. 记录原实例的最后有效快照时点、最终确认写入时点、两种启动回放的摘要和恢复耗时。
